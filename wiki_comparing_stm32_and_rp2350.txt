[[Category:STM32]][[Category:RP2350]]{{metadesc|Comparing STM32 and RP2350}}
The RP2350 is unusual: it has two Arm Cortex-M33 cores ''and'' two Hazard3 RISC-V cores, and the bootrom starts whichever pair matches the image in flash. That makes it possible to compare the two architectures on the exact same silicon, and to put both against well known STM32 parts.

All RP2350 numbers on this page were measured on a [[Streamline]] RP2354 MCU board, flashed and monitored through a Streamline Connect running Hybridlink firmware. Every benchmark runs on '''both cores at the same time'''. Each core reports its own result (the two cores always agree to within 0.1%), and the tables show both the '''per core''' figure and the '''both cores''' total, which is the sum of the two. The source for all benchmarks is in the [https://github.com/RPPicoWorld/rpfun rpfun repository] (see [[#Source code]]).

Compilers used: Arm GNU Toolchain 15.2 (Arm) and the Raspberry Pi RISC-V toolchain RISCV_PICO_2_3_1_0 / GCC 16.1 (RISC-V), Pico SDK 2.3.1, <code>-O3</code>.

== CoreMark ==

[https://github.com/eembc/coremark EEMBC CoreMark] is the most widely published MCU benchmark, so it is the best one for comparing against STM32. The RP2350 runs are standard 2K performance runs, each about 14-16 seconds, and both report "Correct operation validated".

Things to keep in mind when reading the table:
* The STM32 figures are vendor best case, typically built with Arm Compiler or IAR and tuned flags. The RP2350 figures are stock GCC <code>-O3</code>. CoreMark results vary a lot with compiler and settings, which ST itself points out<ref name="st_coremark_howto"/>.
* The STM32H562 has the same Cortex-M33 core as the Arm side of the RP2350, yet ST gets 4.09 CoreMark/MHz versus 2.53 here. Most of that difference is compiler (Arm Compiler vs GCC) and memory: the H562 runs from 0 wait state internal flash, the RP2350 runs from external QSPI flash through a 16 kB XIP cache.
* Even at the stock 150 MHz a single RP2350 core is roughly 4× an STM32F103. Both cores together beat an STM32F405 running at 168 MHz.
* Overclocked to 540 MHz, both Arm cores together (2735) are level with ST's best case figure for the STM32H723 (2778), and both RISC-V cores together (3164) beat it. Per core the Cortex-M7 in the H723 is of course still much faster.
* On the RP2350 the Hazard3 RISC-V core is about 16% faster than the Cortex-M33 in this integer benchmark.

== Dhrystone ==

The results (here and for CoreMark) scale almost perfectly with clock speed. The two cores always score the same as each other, so the both-cores total is essentially twice the per-core figure. Above 320 MHz the flash has to be switched to the slow serial command XIP mode, but because the benchmark lives in the XIP cache this makes no measurable difference.

For reference, ST quotes 1.25 DMIPS/MHz for the STM32F103 (about 90 DMIPS at 72 MHz)<ref name="st_f103"/> and 210 DMIPS at 168 MHz for the STM32F405/407<ref name="st_f4"/>.

This is where the architectures really differ. The Cortex-M33 cores have a single precision FPU (plus the RP2350 double precision coprocessor), while the Hazard3 cores have no FPU at all and do floating point in software. The Pico SDK ships hand optimised Hazard3 routines for single precision add, subtract and multiply (about 37% faster than plain libgcc in this test), but division, the math library and all double precision come from the generic libraries. The result is roughly a 9× advantage for Arm in floating point.

== Summary ==

* Integer code (CoreMark, Dhrystone): the RISC-V cores are 16-20% faster than the Arm cores at the same clock.
* Floating point code (Whetstone): the Arm cores are about 9× faster.
* Per core at stock clock the RP2350 sits between an STM32F1 and an STM32F4. Both cores at stock clock beat an STM32F4. Both cores overclocked to 540 MHz reach STM32H723 level in CoreMark (2735 Arm, 3164 RISC-V vs 2778).

== Source code ==

All benchmarks are in the [https://github.com/RPPicoWorld/rpfun rpfun repository] for the [https://www.youtube.com/@RPPicoWorld RPPicoWorld] YouTube channel. Each pair differs only in <code>PICO_PLATFORM</code> and the toolchain:

* CoreMark: [https://github.com/RPPicoWorld/rpfun/tree/master/examples/coremark_arm coremark_arm] / [https://github.com/RPPicoWorld/rpfun/tree/master/examples/coremark_riscv coremark_riscv]
* Dhrystone: [https://github.com/RPPicoWorld/rpfun/tree/master/examples/dhrystone_arm dhrystone_arm] / [https://github.com/RPPicoWorld/rpfun/tree/master/examples/dhrystone_riscv dhrystone_riscv]
* Whetstone: [https://github.com/RPPicoWorld/rpfun/tree/master/examples/whetstone_arm whetstone_arm] / [https://github.com/RPPicoWorld/rpfun/tree/master/examples/whetstone_riscv whetstone_riscv]

All projects default to the stock 150 MHz / 1.10 V. To overclock, configure with for example <code>-DSYS_CLOCK_KHZ=320000 -DCORE_VOLTAGE=VREG_VOLTAGE_1_30</code> or <code>-DSYS_CLOCK_KHZ=540000 -DCORE_VOLTAGE=VREG_VOLTAGE_1_60</code>. The [https://github.com/RPPicoWorld/rpfun#switching-between-arm-and-risc-v repository README] explains how to flash Arm and RISC-V images back to back with a CMSIS-DAP probe without falling back to BOOTSEL.
